# my-new-project

카드/전략 기반 웹게임 프로토타입. 로그(전투 기록) 중심으로 턴이 진행되며, 가벼운 웹 스택으로 시작해 추후 2D RPG와 모바일 앱스토어 출시까지 확장하는 것을 목표로 합니다.

## 아키텍처

게임 로직과 UI를 분리해서, 나중에 렌더러만 교체하면 2D RPG로 확장할 수 있도록 설계했습니다.

- `src/engine/` — 순수 TypeScript 함수로 작성된 게임 엔진 (`engine.ts`, `cards.ts`, `races.ts`, `monsters.ts`, `dungeon.ts`, `essence.ts`, `gear.ts`, `stats-calc.ts`, `stat-bonus.ts`, `profile.ts`, `auth.ts`, `cloud-profile.ts`, `supabase-client.ts`, `tax.ts`, `body-parts.ts`, `battle-ai.ts`, `consumables.ts`, `npc.ts`, `dungeon-clock.ts`, `village-clock.ts`, `hunting-proficiency.ts`, `session.ts`, `status-effects.ts`, `ritual.ts`, `types.ts`). 카드 사용, 턴 진행 등 모든 액션이 `GameState`를 새로 계산하고 `log` 배열에 이벤트를 기록합니다. DOM이나 렌더링에 전혀 의존하지 않아 UI를 바꿔도 그대로 재사용 가능합니다.
- `src/ui/` — 화면별 렌더링 (`auth`, `menu`, `character-select`, `stats`, `village`, `dungeon-map`, `inventory`, `equipment`, `essence`, `battle`, `shop`, `exchange`, `library`, `ritual`, `temple`). `src/main.ts`는 화면 전환만 담당하는 라우터입니다. 나중에 Phaser 기반 2D 렌더러로 교체해도 엔진은 그대로 둘 수 있습니다.
- **세이브 데이터 필드 추가 원칙**: `PlayerProfile`/`ResumeSession`에 새 필드를 추가할 때는 반드시 (1) `defaultProfile()`에 기본값을 넣고 (2) `sanitizeProfile()`(`profile.ts`)/`sanitizeResumeSession()`(`session.ts`)에도 그 필드의 방어적 기본값 처리를 같이 추가하세요. 이 두 함수가 로컬(`loadProfile`)과 클라우드(`loadCloudProfile`) 저장분을 모두 통과하는 유일한 관문이라, 여기 안 거치면 그 필드가 없는 구버전 세이브에서 `undefined`가 그대로 흘러들어와 조용히 깨질 수 있습니다 (실제로 `floor2Zones` 필드 추가 후 이 처리를 빠뜨려서 구버전 계정의 "이어하기"가 무반응이 되는 버그가 있었습니다).
- **로컬↔클라우드 저장 병합 원칙**: `PlayerProfile.updatedAt`(`profile.ts`)은 로컬 저장이 실제로 일어날 때마다(`main.ts`의 `persistProfileLocalOnly()`) 갱신되는, "이 기기가 마지막으로 이 세이브를 저장한 시각"입니다. 앱 시작 시 이미 로그인된 세션을 조용히 복원할 때(`restoreLoggedInSession`)는 로컬·클라우드 중 이 값이 더 최신인 쪽을 채택하고, 명시적으로 로그인/회원가입할 때(`adoptLoggedInProfile`)는 계정 전환이 목적이므로 클라우드를 우선합니다(둘 다 `syncLoggedInProfile`이 처리). `loadCloudProfile`(`cloud-profile.ts`)은 "저장된 게 없음"과 "네트워크 오류로 확인 못함"을 별도 상태(`CloudProfileResult`)로 구분해서, 일시적 오류를 "빈 세이브"로 오인해 실제 클라우드 데이터를 덮어쓰는 일이 없도록 합니다. 새로 `profile`을 저장하는 경로를 추가할 땐 반드시 `persistProfileLocalOnly()`를 거치게 하세요 — 그렇지 않으면 그 변경이 `updatedAt`에 반영되지 않아 다음 재접속 때 "오래된 변경"으로 오판되어 클라우드의 더 이전 상태로 되돌아갈 수 있습니다(실제로 마을 시계 틱의 세금/판단창 처리가 이 경로를 빠뜨렸던 회귀가 있었습니다).
- **로그인 요청 경쟁 상태 원칙**: 로그인/회원가입/자동 세션 복원은 모두 비동기(Supabase 네트워크 왕복)라, 요청이 끝나기 전에 "게스트로 계속하기"를 누르거나 다시 로그인/로그아웃을 시도할 수 있습니다. `main.ts`는 매 시도마다 증가하는 `authRequestId`를 발급해, 응답이 왔을 때 그 사이 더 최근 시도(게스트 전환 포함)가 있었다면 자신의 결과(클라우드 프로필 채택, 화면 이동 등)를 조용히 버립니다 — 늦게 도착한 로그인 응답이 이미 게스트로 진행 중인 세션을 덮어쓰는 일을 막기 위함입니다.

## 시작하기

```bash
npm install
npm run dev       # 개발 서버 실행
npm run build      # 프로덕션 빌드 (dist/)
```

## 현재 구현된 것

- **로그인 / 클라우드 저장**: 앱 진입 시 아이디·비밀번호로 로그인하거나 "게스트로 계속하기"를 선택. 로그인하면 진행 상황(레벨, 인벤토리, 장비, 정수 등)이 [Supabase](https://supabase.com) 계정에 저장되어 다른 기기에서도 이어할 수 있고, 게스트는 이 브라우저의 `localStorage`에만 저장됨. 로그인 없이도 게임은 항상 완전히 동작함 (설정 방법은 `supabase/README.md` 참고)
  - 같은 탭에서 새로고침해 이미 로그인된 세션이 자동 복원될 때는 로컬·클라우드 중 더 최근에 저장된 쪽을 채택하고(위 "로컬↔클라우드 저장 병합 원칙" 참고), 클라우드 조회가 네트워크 오류로 실패하면 절대 어느 쪽도 덮어쓰지 않고 로컬 상태 그대로 계속 진행함 — 일시적 오류로 실제 진행 상황이 사라지는 일을 막기 위함
  - 내부적으로 "아이디"를 가짜 이메일로 변환해 Supabase Auth의 이메일/비밀번호 로그인을 그대로 사용하므로, 나중에 실제 이메일 인증이나 구글 등 소셜 로그인으로 확장할 때 설정만 추가하면 됨 (게임 로직 변경 불필요)
  - 계정에는 `is_admin` 플래그가 있어 향후 관리자 전용 기능의 기반이 됨. 일반 로그인 경로로는 스스로 켤 수 없고 Supabase SQL Editor에서만 설정 가능 (`supabase/README.md`의 "admin 계정 만들기" 참고). 로그인 시 관리자 계정이면 메인 메뉴에 "관리자" 표시가 뜸
- **캐릭터는 계정당 1개만 존재**: 메인 메뉴 버튼이 캐릭터 유무에 따라 자동으로 바뀜 — 캐릭터가 없으면 "캐릭터 생성"(종족 선택으로 이동), 있으면 "이어하기"(종족 선택을 건너뛰고 바로 진행). 사망 시 세이브 전체 초기화와 자연스럽게 맞물려, 죽고 나면 다시 "캐릭터 생성"이 뜸
  - 종족 선택은 마을 진입 순간 확정됨. 마을의 "뒤로" 버튼은 캐릭터가 아직 없을 때(생성 과정 중)만 보이고, 캐릭터가 이미 있으면 아예 뜨지 않아 다시 종족 선택으로 돌아가 덮어쓸 방법이 없음
- **이어하기 = 종료 직전 화면 그대로 복원**: 마을/스텟창/상점/도서관은 물론, 미궁 탐험 중이던 정확한 위치(미로 구조 포함)나 **전투 중이던 상태(카드 패, 덱 순서, HP, 로그까지)** 도 그대로 복원됨. 화면 전환·전투 진행이 있을 때마다 저장되므로 언제 닫아도 정확히 그 지점부터 이어짐
  - 마을에 "게임 종료" 버튼이 있어 메인 메뉴로 돌아갈 수 있음. 로그아웃이나 세이브 초기화가 아니라 순수 화면 이동일 뿐이라 진행 상황(레벨/스톤/시계 등)은 그대로 유지되고, 메인 메뉴에서 "이어하기"를 누르면 나가기 직전 마을로 정확히 복귀함. 판단 대기 패널이 떠 있는 동안은 다른 마을 버튼들과 마찬가지로 비활성화됨
- **미궁에 들어가면 스스로는 되돌릴 수 없음**: 미궁 진입 후엔 탐험을 계속하거나 사망(전체 초기화)하는 것 외에 마을로 되돌아갈 방법이 없음 — "메인 메뉴로" 같은 탈출 버튼이 없음. 잠시 멈추고 싶다면 탭을 닫았다가 나중에 "이어하기"로 정확히 같은 지점부터 재개하면 됨. 예전엔 미궁 안에서 마을로 나갔다가 새 미궁으로 재진입하면 이미 발견한 포탈의 경험치 보너스를 위험 부담 없이 무한 반복 획득할 수 있었는데, 이 탈출구 자체를 없애 막음. 다만 아래 "미궁 내부 시계"에 의한 **강제 귀환**은 예외 — 이건 플레이어가 원해서가 아니라 시간이 다 되어 자동으로 일어나는 것
- 인벤토리/장비창/정수창은 게임 진입 후(캐릭터 정보 화면, 마을, 탐험/전투 화면) 안에서만 접근 가능
- 종족 선택 → **마을** → 캐릭터 정보(스텟창) → **미궁 입장**
  - 마을에서 인벤토리·장비창으로 바로 이동 가능(뒤로 가면 다시 마을로)
  - 마을에 "상점"·"도서관"·"신전" 진입점이 있음 — "도서관"은 현재 진입/이탈만 가능한 빈 화면. "상점"은 회중시계(아래 참고)와 붕대·포션(아래 "소모품" 참고) 3종만 판매하는 초기 상태이고, 그 외 품목/콘텐츠는 이후 별도 작업에서 채울 예정. "신전"은 정수 해제 전용 시설(아래 "정수(essence)" 항목 참고). "환전소"는 아래 별도 항목 참고(첫 미궁 진입 전까지 잠김이라는 점을 제외하면 활성화 이후엔 실제 기능이 있는 시설)
  - **마을 시계**: 게임 내 하루 = 실시간 120초(1시간 = 5초). 앱이 열려있고 활성 미궁 런이 없을 때만 흐름(미궁 안에서는 멈춤, 탭을 닫아도 멈춤). 마을 화면에 현재 며칠째·몇 시인지 표시되고, 1×/2×/4× 배속과 "다음 판단 시점까지 스킵"(30일 주기 자정(00:00) 지점으로 즉시 이동) 가능
  - **미궁 입장은 더 이상 아무 때나 즉시 할 수 없음**: 예전엔 스텟창의 "미궁 입장" 버튼으로 언제든 바로 들어갈 수 있었지만, 지금은 그 버튼이 "미궁 입장까지 남은 시간" 표시로 바뀌었고(마을·스텟창 양쪽), 게임 내 30일마다 자정(00:00)이 되면 마을 화면에 **입장 여부를 묻는 판단창**이 뜸 — 이때만 입장 가능. 판단창이 뜨면 실시간 30초 안에 "입장한다"/"거부한다"를 선택해야 하고, 응답이 없으면 자동으로 거부 처리되며 시계는 계속 흐름 (다른 마을 화면에 있었다면 마을 화면으로 돌아오는 즉시 판단창이 뜸, 그동안은 마을의 다른 모든 버튼이 잠김). "거부"해도 성과는 그대로 유지되고 다음 판단 시점을 기다리면 됨
- **미궁 탐험 (1층: 원형 미로, 2층: 구역별 4개의 별개 미궁)**
  - **1층 구조**: 중심부(1칸) + 중간 고리(8칸) + 가장자리 고리(8칸, 그중 4칸이 동서남북 포탈)로 이루어진 원형 미로. 중심부↔중간 고리↔가장자리 사이의 통로는 매번 랜덤 생성되어 막다른 길이 있을 수 있지만, **가장자리 고리는 항상 완전히 순환 연결**되어 있어 포탈끼리는 물론 어떤 가장자리 칸에서도 막힘 없이 동서남북을 오갈 수 있음 (1000회 생성 시뮬레이션에서 항상 성립 확인)
  - 각 칸마다 실제로 뚫려있는 방향만 이동 선택지로 제공됨 (칸에 따라 개수가 다름)
  - 구역마다 테마에 맞는 몬스터가 출몰 (1층 기준 북쪽은 노움, 동쪽은 칼날늑대, 남쪽은 고블린, 서쪽은 구울). 중심부는 4구역의 몬스터가 모두 섞여서 출몰
  - 미궁/2층 입장 시 중심부 또는 중간 고리에 랜덤 배치되고, 미로 자체가 매번 새로 생성되므로 포탈까지 몇 걸음이 필요한지는 입장할 때마다 달라짐
  - **최초 입장 시에도** 확률적으로 전투가 발생할 수 있고, 이후 이동할 때도 매번 같은 확률로만 전투가 발생 (포탈로 향하는 이동은 전투 없이 항상 안전)
  - 각 이동 선택지에는 "전투 확률 55%" 또는 포탈인 경우 "전투 없음"이 함께 표시되어, 어느 방향이 안전한지 미리 알 수 있음
  - 동서남북 끝에 포탈비석이 있으며, 처음 발견하면 경험치 +2 획득. 1층에서는 "이 포탈로 2층 입장"을 선택하면 그 포탈 방향 전용의 **2층 미궁**으로 들어감 — 즉 2층은 방향에 따라 완전히 별개인 4개의 미궁으로 나뉨. 몬스터 로스터도 층마다 완전히 다름(예: 1층 북쪽은 노움뿐이지만 2층 북쪽인 고블린 숲은 고블린 검사/궁수) — 같은 방향이라고 1층 몬스터가 2층에서도 나오는 게 아니라, 그 방향의 2층 전용 몬스터로 완전히 바뀜
  - **고블린 덫**: 1층 남쪽 구역 일부 칸에 있으며, 미리 "덫 감지"로 표시됨 — 눈에 뻔히 보이는 덫을 일부러 밟을 이유가 없다는 점을 반영해, 그 칸으로 이동하면 선택의 여지 없이 그 자리에 숨어있던 고블린에게 반드시 기습당함(1턴 기절). 이겨서 그 고블린을 처치하면 같은 칸은 이후로 안전해짐(다른 칸으로 돌아가는 건 항상 가능)
  - **2층**은 아직 그 다음 층으로 넘어가는 기능 없이(추후 이어서 구현 예정), 포탈 도달 시 경험치 +2와 "다음 구간은 준비 중" 안내만 표시됨. 대신 2층의 포탈에서 **"1층으로 귀환"**을 선택할 수 있음 (미궁 내부 시계 누적 7일이 지나면 이 선택지가 사라지고 더 이상 1층으로 못 돌아감)
  - **최초 진입을 제외한 모든 역행은 항상 재사용이 원칙**: 1층↔2층을 오갈 때마다 새 미로를 만들지 않고, 그 자리(1층, 그리고 2층은 방향별로 각각)를 떠날 때 마지막 상태를 저장해뒀다가 나중에 같은 곳으로 돌아오면 그대로 이어서 사용함 — 포탈 재파밍 악용을 다시 열지 않기 위한 원칙
  - **몬스터 등급은 1등급이 최강, 9등급이 최약인 등급제** (숫자가 작을수록 강함). 층(F)이 깊어질수록 더 강한(숫자가 작은) 등급을 목표로 몬스터가 골라짐 — 1층은 9·8등급이 주류(약 80%)에 가끔 7등급(약 20%), 깊은 층일수록 목표 등급이 1등급 쪽으로 수렴하고 9층 이후는 항상 1등급만 등장(최댓값 고정)
  - **몬스터 무리 스폰**: 미궁에 체류한 일수가 늘수록 무작위 조우 한 번에 연속으로 싸워야 하는 마릿수가 늘어남 — 1일차는 단독, 2일차는 2마리, 3일차부터는 3~4마리(1층 기준, 7일 폐쇄까지 유지). 진짜 다중 전투가 아니라 이긴 직후 같은 자리에서 바로 다음 상대가 이어지는 방식(전투 화면에 "무리 2/4"처럼 진행률 표시), 쉬지 않고 이어지는 소모전 자체가 위협이 되도록 함. 함정 기습처럼 몬스터가 특정 개체로 강제되는 조우는 무리에서 제외. 2층은 훨씬 가파르게 늘어남(최대 8~12마리) — 정확한 수치는 디자인 노트에도 명시되어 있지 않은 1차 추정치
  - **미궁 내부 시계**: 게임 내 하루 = 실시간 60초(1시간 = 2.5초, 마을 시계보다 빠름, 배속 조절 불가). 입장 시점부터 누적으로 흐르고 층을 옮겨도 리셋 안 됨. 누적 7일이 되면 1층에 있을 경우 **강제로 마을로 귀환**(전투 중이라도 즉시, 유예 없음)되고, 누적 10일이 되면 2층에 있을 경우 마찬가지로 강제 귀환됨. 그때까지 얻은 레벨/경험치/정수/마석/장비는 그대로 유지되고(사망이 아님), 마을 시계는 실제 미궁 체류 기간과 무관하게 "입장한 날 정오"로 고정됨. (엔진에는 강제 귀환 시 비영구(`isPermanent` 아닌) 장비만 걸러내는 `stripDungeonOnlyGear`(`src/engine/profile.ts`)가 있지만, 몬스터 처치로는 더 이상 장비가 드랍되지 않아 지금은 걸러질 대상이 없음 — 넘버링 아이템 등 미궁 한정 전리품이 생기면 다시 쓰일 장치)
    - 미궁 안(미궁 지도/전투/그 상태로 연 인벤토리·장비창·정수창)에서도 마을과 같은 "N일차 HH:MM" 형식으로 이 시계가 표시되고, 흐르는 대로 실시간 갱신됨. 이 표시는 **"회중시계"를 장신구 슬롯에 장착해야만 켜지는 기능**(`isClockVisible`, `src/engine/profile.ts`) — 마을 **상점**에서 300스톤에 구매하는 장비이며(`buyPocketWatch`, 상점의 첫 판매 품목), 순수 스탯 보너스는 없고 오직 이 시계 표시 하나만을 위한 아이템임. 미궁 한정이 아니라 영구 보유 장비라 강제 귀환해도 사라지지 않고, 이미 보유 중이면 상점에서 다시 구매할 수 없음
- **몬스터는 디자인 노트(`designnotes.md` 4-3번)의 로스터를 그대로 따름**: 1층 4종(고블린·구울·칼날늑대·노움, 전부 9등급, 구역당 1종) + 2층 14종(고블린 숲/망자의 땅/검은 바위산/짐승의 소굴 구역별로 여러 종). 디자인 노트에 없는 전투 수치(마나·스킬 값·정수/장비 보너스)는 전부 코드에서 임의로 잡은 1차 초안이라 요청하면 언제든 바꿀 수 있음. 각 몬스터는 정해진 층·구역에서만 등장하므로 1층과 2층은 로스터가 완전히 겹치지 않음
- **스탯 체계 — 육체/정신/이능 3대 메인스탯 + 세부스탯 12종**: 종족마다 육체·정신·이능과 최대체력·최대마나가 고정값으로 정해져 있고, 여기에 세부스탯이 딸림 — 육체(근력/유연성/시각/명중률), 정신(인지력/손재주/인내심/민첩성), 이능(후각/독내성/인식방해/집착). 장비·정수가 부여하는 보너스도 이 필드들에 그대로 가산됨(`src/engine/stat-bonus.ts`). **이능은 장착 중인 정수 스킬 카드의 위력 배율**(1당 +5%, `src/engine/engine.ts`의 `ARCANE_ESSENCE_COEF`)로 쓰임 — 기본 카드 풀(공격/방어)에는 영향 없음
  - 캐릭터 정보 화면에는 위 스탯들의 합산 결과(최대체력/최대마나)와 파생값인 **아이템 레벨**(장착 장비가 부여하는 보너스 총합), **종합 전투 지수**(전투 판정에는 쓰이지 않는 표시 전용 가중합)가 함께 표시되고, 세부스탯 12종은 접이식으로 기본 숨김. 장비창/인벤토리의 각 장비에는 "Lv.N" 아이템 레벨 배지가 붙음
- 종족별 고정 스텟: 바바리안, 인간, 요정, 드워프, 수인
  - **현재 선택 가능한 종족은 바바리안뿐**. 나머지(인간/요정/드워프/수인)는 종족 선택 화면에 "잠김" 배지가 붙은 채로 표시되며 클릭해도 선택되지 않음(추후 공개 예정). 오크는 플레이어 종족에서 완전히 삭제됨. 과거 오크로 생성된 기존 캐릭터는 세이브 스키마 버전 상승으로 인해 다음 접속 시 전체 초기화됨
  - **바바리안 성인식**: 캐릭터 생성 시 무기 6종(활 포함, 명중률 세부스탯을 채우는 최초 장비) 중 1개 선택 + 기본 방어구 자동 지급
- **플레이어 vs 몬스터 턴제 카드 배틀**, 자동 적 AI 턴. **마나는 카드를 쓰기 위한 자원일 뿐, 라운드당 몇 번 카드를 낼 수 있는지는 별도의 공격속도가 정함**(민첩성 3당 +1행동, 기본 1행동, 최대 3행동 — `src/engine/engine.ts`의 `attackSpeed()`) — 예전엔 "마나가 남고 낼 수 있는 카드가 있는 한 계속 낸다"는 규칙이라 몬스터마다 제각각인 마나량이 그대로 숨은 전투력 배수로 작용했는데(2층 몬스터가 플레이어보다 훨씬 자주 때리는 문제, `designnotes.md` 3-1/3-10번), 이 둘을 분리해 해결함. 전투 화면에 "행동력 N/M"으로 표시되고, 마나가 남아있어도 행동력이 0이면 카드를 낼 수 없음. 기본 카드 덱은 공격/방어 카드로만 구성됨 — 전투 중 회복은 카드로 제공하지 않기로 확정되어 기본 덱에는 회복 카드가 없고(과거의 "응급처치" 카드는 제거됨), 회복 이펙트(`heal`)는 엔진에 남아있어 향후 정수 스킬 카드가 활용할 수 있음. 공격 카드는 **명중 판정**(기본 90%, 공격자 명중률↑·방어자 유연성↓·방어자 인식방해↓로 조정되며 20~99% 사이로 제한)을 먼저 통과해야 피해가 들어가고 — 실패하면 "회피했다!"만 로그에 남고 피해 없음(카드 코스트/마나는 정상 소비) — 성공 시엔 이어서 **치명타 판정**(기본 5%, 공격자 유연성↑)을 확인해 성공하면 피해에 배율(기본 1.5배, 공격자 집착↑만큼 가산, 최대 2.0배)이 곱해짐. 최종 피해는 `카드 값 × (1 + 근력 × 10%) × (치명타 시 배율) × (1 − 방어력 감소율)`이며, 방어/회복 카드는 이 판정 없이 그대로 적용됨(`src/engine/engine.ts`)
  - **즉사(헤드샷 등)**: 몬스터가 플레이어를 명중시켰을 때만 별도로 확인하는, 체력·치명타와 완전히 무관한 위험 축. 근접 몬스터도 등급이 높을수록(더 강할수록) 아주 낮은 확률로 즉사를 유발할 수 있고, 원거리(활) 몬스터는 "헤드샷" 고정 확률이 그 위에 더해짐 — 1층 9등급 몬스터(전부 근접)는 확률이 정확히 0%. 투구 같은 방어 수단은 아직 없음(장비 슬롯 확장 시 추가 예정)
- **상태이상**: 독(스택당 피해, 독내성으로 경감)/출혈(스택당 피해)/기절(해당 턴 행동 불가) 3종
- **부위 손상**: HP·상태이상과 완전히 독립된 세 번째 축(`src/engine/body-parts.ts`). 명중한 공격마다 8% 확률로 방어자의 몸통/왼팔/오른팔/왼다리/오른다리 중 아직 손상 안 된 부위 하나가 손상되어, 해당 전투가 끝날 때까지 실제 스탯이 즉시 깎임(팔→명중률 -3, 다리→유연성 -3, 몸통→인내심 -3). 같은 부위는 그 전투 동안 두 번 손상되지 않고, 머리는 대상에서 제외(머리는 기존 즉사/헤드샷 판정이 이미 담당). 확률·페널티 수치는 1차 추정치이고, 전투를 넘어선 영구 부상·치료 수단은 아직 미구현(추후 확장 여지)
- 몬스터 등급(1~9, 1등급이 최강)에 따른 경험치 획득(강한 몬스터일수록 경험치 많음), 같은 이름의 몬스터는 최초 처치 시에만 경험치 지급
- **사냥 숙련도**: 몬스터 종류별로 처치 횟수가 쌓이면(`PlayerProfile.monsterKillCounts`, `src/engine/hunting-proficiency.ts`) 그 몬스터를 상대로만 명중률/유연성/손재주가 조금씩 올라 전투가 쉬워짐(4처치당 1티어, 최대 5티어). exp와 달리 같은 몬스터를 반복 처치해도 계속 누적되며, 완전히 다른 몬스터에는 적용되지 않아 특정 상대에 익숙해질수록 안전해지는 감각을 의도된 성장으로 제공. 전투 화면에 "숙련도 Lv.N" 배지로 표시되고 새 티어를 밟으면 전투 로그에 안내가 남음
- 레벨/경험치는 `localStorage`에 저장되어 브라우저를 다시 열어도 유지됨, 스텟창에 표시
- **업적**: HP가 2%/0.1% 이하로 떨어졌다가 생존, 몬스터 첫 처치 시 정신 스탯 영구 상승(캐릭터 생애 1회씩, 사망 시 초기화)
- **영구 사망(퍼머데스)**: 전투에서 패배하면 레벨/경험치/인벤토리/장비/정수/마석/발견 도감 등 모든 진행 상황이 초기화되고 메인 메뉴로 돌아감 (로그인 계정도 클라우드 저장분이 함께 초기화됨)
- **인간형 NPC 조우 (전투불능)**: 미궁 이동 중 몬스터 대신 아주 낮은 확률로 적대적인 인간형 NPC("떠돌이 탐험가", `src/engine/npc.ts`)와 마주칠 수 있음. 몬스터와 달리 HP가 0이 되어도 죽지 않고 "전투불능" 상태로 전투가 끝나며, 그 자리에서 **동료로 삼거나 / 살려주거나(보상 없음) / 끝장낼지(스톤 획득)** 선택 가능. 몬스터 전용 파이프라인(경험치/마석/장비드랍/정수)과는 완전히 분리된 시스템
- **파티(동료 NPC, 최대 1명)**: 전투불능 상태의 NPC를 "동료로 삼으면" 그 이후 모든 전투(몬스터/NPC 불문)에 자동으로 함께 싸움 — 플레이어 턴 다음, 적 턴 이전에 스스로 카드를 냄(수동 조작 불가). 전투 화면에 세 번째 액터 패널로 표시되고, 적은 매 공격마다 플레이어와 동료 중 무작위로 노림. **동료가 쓰러져도 게임 오버가 아님** — 페르마데스(전체 초기화)는 여전히 플레이어 HP 0에만 걸리고, 동료는 조용히 전투에서 이탈할 뿐. 동료 HP는 전투마다 초기화되며(이월 없음), 교체/해산 UI나 유지 시간 제한은 아직 없음(죽거나 캐릭터가 사망할 때까지 유지)
- **자동전투 — 언제든 켜고 끌 수 있는 on/off 모드**: 전투 시작 시 실제 게임 엔진으로 300회 시뮬레이션을 돌려 승률을 추정해 "자동전투 시작" 버튼에 "예상 승률 N%"로 표시(99% 이상이면 그대로, 미만이면 "위험할 수 있습니다" 문구 추가)하지만 어디까지나 문구일 뿐 — 승률과 무관하게 항상 켤 수 있고, 켜져 있는 동안엔 같은 자동 플레이 로직이 매 턴 자동으로 카드를 내며 진행하다가 "수동으로 전환"으로 언제든 되돌아올 수 있음 (승리를 보장하지 않고 실제 확률 그대로 결과가 나옴)
  - **켜두면 한 번만 켜면 됨**: 자동전투는 그 전투 한 판이 아니라 켜고 끄는 지속적인 설정이라, 한 번 켜두면 승리 후 다음 무작위 조우·무리(pack)의 다음 상대·인벤토리 등 서브화면에 갔다가 돌아오는 경우까지 계속 자동으로 유지됨(전투를 완전히 벗어나 있는 동안엔 타이머만 잠시 멈췄다가, 다시 전투 화면으로 돌아오면 재개). 새로고침(이어하기)이나 사망/강제 귀환 후에는 항상 수동으로 되돌아감
  - **로그 복사**: 전투 화면 로그 영역의 "로그 복사" 버튼으로 지금까지의 전투 로그 전체를 클립보드에 텍스트로 복사할 수 있음 (버그 제보 등에 사용)
- **정수(essence) — 흡수형 장착**: 몬스터 처치 시 0.1% 확률로 그 몬스터 고유의 정수가 드랍. 그 자리에서 흡수할지 버릴지만 선택 가능 (별도 보관 없음). 흡수하면 레벨당 1개씩 열리는 슬롯에 순서대로 영구 장착됨 (장비창처럼 자유롭게 뺄 수 없음 — 마을 **신전**에서 스톤을 내야만 해제 가능. **캐릭터당 평생 딱 3회**로 엄격히 제한되며, 1회차 500만/2회차 1,000만/3회차 2,000만 스톤으로 회차마다 값이 크게 오름. 해제된 정수는 보관되지 않고 사라져, 다시 얻으려면 같은 몬스터를 처치해 정수를 재드랍받아야 함). 각 정수는 드랍된 몬스터의 특성을 반영한 고정 스텟 보너스 + 전용 스킬 카드를 부여하고, 이 스킬 카드의 위력은 이능 스탯에 비례해 강해짐(위 "스탯 체계" 참고)
- **장비(무기/방어구/장신구) — 몸에 착용하는 일반 장비**: 정수와 완전히 별개 시스템. 캐릭터 생성 시 바바리안 성인식으로 무기+방어구가 자동 지급되고, 마을 상점에서 회중시계(장신구)를 구매할 수 있음. 장비창에서 자유롭게 장착·해제 가능(해제하면 다시 인벤토리로)
  - **몬스터를 처치해도 장비는 얻을 수 없음**: 몬스터는 죽으면 장비를 남기지 않고 빛나는 먼지가 되어 사라짐(설계 확정 사항). 몬스터에게서 얻을 수 있는 건 마석뿐 — 넘버링 아이템(보스급/특수 개체 한정 드랍)과 부속물(특정 마법으로 시체를 보존한 뒤 해체해서 얻는 아이템) 체계는 구상 단계이며 아직 미구현
  - **장비 내구도**: 성인식 방어구 중 상의(내구도 15)와 신발(내구도 6)에만 부여됨(`src/engine/gear.ts`). 전투 중 몸통 부위가 손상되면 상의가, 다리 부위가 손상되면 신발이 내구도 1씩 깎이고(위 "부위 손상" 참고), 0이 되면 그 장비는 수리·회수 없이 완전히 사라짐. 하의는 아직 내구도 개념이 없음(1차 구현, 수치는 추정치)
- **소모품 — 장착도 흡수도 아닌, 들고 다니다 "사용"하면 사라지는 새 아이템 카테고리**(`src/engine/consumables.ts`): 마석처럼 개수만 세는 카운터로 보관됨. **붕대**(마을 상점에서 30스톤에 구매, 반복 구매 가능) — 전투 화면에서 "붕대 사용" 버튼으로 자신의 **출혈 상태이상을 완전히 치료**할 수 있음(보유 중이고 출혈 상태일 때만 버튼 활성화, 수동 전투 중에만 사용 가능, 스택 수와 무관하게 한 번에 완치, 마나·턴 소모 없음). **포션**(마을 상점에서 80스톤에 구매) — 사용하면 **최대체력의 40%를 즉시 회복**함. "전투 중 회복은 정수 스킬로만, 포션은 미궁 이동/휴식 중에만" 결정(`designnotes.md` 2번 섹션)에 따라 전투 화면에는 사용 버튼이 아예 없고 **미궁 지도(이동) 화면에서만** 사용 가능 — 이 결정에 맞춰 미궁 지도 화면에 그동안 없던 현재 체력(HP) 바도 함께 추가됨. 체력이 이미 가득 찼거나 보유 수량이 0이면 버튼이 비활성화되고(0개면 버튼 자체가 사라짐), 최대체력을 넘는 과충전은 없음. 두 소모품 모두 인벤토리 화면에 보유 수량 표시. 나침반/수통/식량 등 나머지 후보 소모품은 각각 연결될 시스템(생존 수치 등)이 아직 없어 미구현
- **마석 — 등급별 드랍**: 몬스터 처치 시 90% 확률로 드랍되며, 그 몬스터의 등급(1~9, 1등급이 최강)에 해당하는 마석이 쌓임. 인벤토리에서 등급별로 구분되어 표시됨 (예: "3등급 마석 x2")
- **환전소 — 마석을 스톤으로 교환**: 마을 시설. 첫 미궁 진입 후 처음으로 마을에 복귀(강제 귀환)하면 활성화되고, 그 전까지는 "잠김" 배지가 붙은 채 비활성화되어 있음(사망 시 다시 잠김). 등급별로 보유한 마석 전량을 한 번에 정해진 환율로 스톤과 교환 가능 — 같은 등급의 마석은 가치가 모두 동일. 환율은 9등급 20스톤부터 1등급 2,000스톤까지, 등급이 오를수록 배율이 완만해지는 곡선(실제 구현된 1~2층 기준으로 재검증됨 — 아래 연간 세금 시스템 참고)
- **연간 세금 시스템 (현재 비활성화)**: 게임 내 1년(=360일=30일 판단 주기 12번)마다 마을에서 70만 스톤을 징수함. 캐릭터는 게임 시작부터 이미 20세로 간주되어 즉시 과세 대상이며, 첫 번째 연차 경계(360일)부터 곧바로 정상 징수됨(별도의 "1년차 면제" 없음 — 물론 360일이 지나기 전엔 애초에 청구될 게 없다는 당연한 사실은 그대로). 미납 시 기존 전투 패배와 동일한 페르마데스(세이브 전체 초기화) 처리되며, 메인 메뉴에 "세금을 내지 못해 파산했습니다" 안내가 별도로 표시됨. 정상 납부 시엔 마을 화면에 "N년차 세금 700,000스톤이 징수되었습니다" 1회성 안내가 뜸. 미궁에 머무는 동안엔 마을 시계가 멈추므로 징수 시점이 미궁 밖으로 나올 때까지 지연될 수는 있지만, 강제 귀환 시점에 소급 적용되어 미궁에만 머물러 세금을 영구히 회피하는 것은 불가능함. **`src/engine/tax.ts`의 `TAX_SYSTEM_ENABLED` 상수 하나로 전체 on/off 제어** — 현재는 `false`로 꺼져 있음. 실제 구현된 1~2층 기준으로 환전 경제를 재검증한 결과, 연간 최대 기대 수입(~14.6만 스톤)이 70만 세금과 80만 혼령각인(미구현) 모두에 크게 못 미치는 것으로 확인됨 — 두 지출 모두 아직 없는 3층 이상 콘텐츠를 전제로 한 목표이므로, 3층 이상 미궁이 실제로 구현될 때까지 계속 OFF로 유지하기로 함. 꺼져 있는 동안에도 "몇 년차까지 정산됐는지"(`lastTaxedYear`)는 조용히 계속 갱신되므로, 나중에 켰을 때 그동안 지난 여러 해가 한꺼번에 청구되는 일은 없음
- 장착한 정수와 장비의 스텟 보너스는 모두 종족 스텟에 합산되고, 정수 스킬은 전투 덱에 추가됨
- **화면 3분리**:
  - `인벤토리` — 등급별 마석, 미착용 장비, 스톤 표시(스톤은 드랍되지 않고 표시만)
  - `장비창` — 무기/방어구/장신구 슬롯. 자유롭게 장착·해제
  - `정수 창` — 지금 장착 중인 정수 목록 + 지금까지 발견한 정수 도감(흡수 안 해도 발견 기록은 남음)
- 모든 행동이 로그로 기록되고 화면에 누적 표시

## 클라우드 저장(로그인) 설정

로그인 기능을 실제로 켜려면 무료 Supabase 프로젝트가 하나 필요합니다. 자세한 단계는 [`supabase/README.md`](./supabase/README.md)를 참고하세요. 요약하면:

1. Supabase 프로젝트 생성 후 `supabase/schema.sql` 실행
2. Authentication → Providers → Email에서 **Confirm email** 끄기
3. Project URL / anon key를 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`로 Render 환경변수에 등록 후 재배포 (로컬은 `.env.local`)

이 값들이 없으면 앱은 자동으로 게스트 전용 모드로 동작합니다.
